CLAUDE HANDOFF - AGENT FACTORY LEARNING SYSTEM
Version: 0.1

OBJECTIVE
Implement the learning architecture described in the accompanying files.
Do not reduce this to a static quiz system.

KEY BEHAVIOR
1. Student and Trainer both learn.
2. Trainer continuously improves tests.
3. Learning cannot advance without evidence from testing.
4. Important lessons must be reiterated and applied.
5. Disputes can create a temporary Judge.
6. Judge sees the relevant combined knowledge of both sides for that dispute.
7. Judge returns a ruling and reusable lesson, then terminates.
8. Useful corrections are persisted; temporary Judge identity is not.
9. New agents are bootstrapped from shared knowledge and validated experience.
10. New agents should be effective from the start, then improve.

REQUIRED WORKFLOW
lesson
-> student reiteration
-> practice
-> trainer test
-> pass/fail/dispute
-> optional Judge
-> correction
-> persistence
-> retest
-> mastery update
-> next lesson

ACCEPTANCE TESTS

TEST 1 - REITERATION
After a lesson, Student must restate, explain, give example, and apply it.

TEST 2 - ADAPTIVE TESTING
After repeated success, Trainer must generate a harder or more novel test.

TEST 3 - REMEDIATION
After repeated failure, Trainer must change instruction or practice rather than repeat the same test forever.

TEST 4 - JUDGE
When Student and Trainer make conflicting plausible claims, temporary Judge is created with both evidence sets and returns a ruling.

TEST 5 - JUDGE EPHEMERALITY
Judge identity/session is not required after resolution.
The ruling and lesson remain.

TEST 6 - KNOWLEDGE REUSE
A second newly created agent can receive a validated reusable lesson generated by the first agent's training.

TEST 7 - NO FALSE MASTERY
Consuming lessons without passing application tests must not increase mastery to proficient levels.

TEST 8 - TEST EVOLUTION
Training history must show that test difficulty/novelty increases as capability increases.

TEST 9 - HARD VS HEURISTIC
System must distinguish immutable/validated rules from defeasible learned judgments.

TEST 10 - FACTORY RELEASE
Agent cannot be promoted to client deployment unless configured release gates pass.

IMPLEMENTATION PRINCIPLE
Keep the architecture domain-independent.
Music is the first pilot, not a hard-coded assumption.

PERSISTENCE PRINCIPLE
Persist what is expensive or impossible to recreate:
validated knowledge, lessons, procedures, progress, failures, preferences, rulings.
Avoid persisting disposable derived state unless needed for audit/debugging.

NEXT PRACTICAL STEP
